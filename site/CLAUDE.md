# site/CLAUDE.md - build spec

What `build_site.py` is and how it is laid out, so a new session can change the page
without re-reading 900 lines first. The root `CLAUDE.md` owns the workbook, the data
rules and the editorial voice, and **wins on any conflict**; this file owns the generator.

Read this before touching `build_site.py`, `chrome.css`, `extra.css` or `site.js`.

---

## 1. The pipeline

```
S1 NY Islanders.xlsx  ->  site/build_site.py  ->  index.html + version.txt
                                                 (repo root, GitHub Pages serves main)
```

`site/deploy.sh` is the only publish path: it rebuilds, refuses non-ASCII output or a
build-id mismatch between `version.txt` and `<meta name="build">`, `git add -A`, commits
and pushes the current branch. Then fast-forward `main` and push it too - Pages serves
`main`.

`index.html` is one self-contained file: CSS, JS, club crests and player photos are all
inlined (crests as `data:` URIs behind `.lg-XXX` classes, generated by `logo_css()`).
Nothing is fetched at runtime except `version.txt` and `sw.js`.

## 2. Order of `build_site.py`

Top-level code runs in file order; every section builds an HTML string that `TABS`
assembles at the end. To add something, build the string in the matching section.

| Line-ish | Section | What lives there |
|---|---|---|
| helpers | `esc` `mnum` `money` `rows` `data_uri` `assert_ascii` | `rows()` reads **from row 3**; row 2 is the styled template |
| data | the `wb[...]` loads | every sheet becomes a list of `OrderedDict`s keyed by row 1 |
| season aggregates | `GF` `GA` `PP_G` `BLL` `rec_of` ... | derived once, used by tiles and copy |
| pieces | `empty` `sec` `tile` `table` `td` | the only HTML primitives; use them, don't hand-roll markup |
| players | `pkey` `pname` `linkify` `player_card` `player_modal` | `pname()` makes any roster name a button; `linkify()` turns `<b>Surname</b>` in editorial copy into one |
| logos | `logo_css` `tlogo` | `tlogo(abbr, "xs"/"sm"/"mid"/"big")` |
| hero | `record_html` `phase_pill` `nextgame` | |
| overview | `overview` | strip, Inside the Numbers, Recent Headlines, Game Log, Skating/Goaltending |
| roster | `roster_html` | Main Roster, Goalies, In the System |
| lines | `lines_html` | `unit_card()` per `Lines` unit |
| front office | `fo` | strip, General Manager (`gm`: Transactions ledger + Extension Eligible), Owner, Owner Goals, Budget, Cap, Cap Rules |
| news | `news_html` | the transaction wire (see below) |
| schedule / goalies / teams | `schedule_html` `goalies_html` `teams_html` | |
| page | `TABS`, `page = """..."""` | |

## 3. Adding a tab

One line in `TABS`, nothing else. `site.js` binds tabs by `data-panel` and panels by
`id`, both generated from the same tuple, so a new entry wires itself up.

```python
TABS = [..., ("p-news", "News", news_html), ...]
```

`.tabs` is a CSS grid with `auto-fit, minmax(108px, 1fr)` and a 2-column phone override,
so the bar wraps; it never scrolls sideways. Check the tab count still lands without an
orphan on a row of its own.

## 4. The news wire

`news_panel()` generates the News tab **from the `Transactions` sheet** - there is no
News sheet and no prose column. One card per row, grouped by date, newest day first;
`news_line()` turns the columns into one plain sentence per `Type`:

| `Type` | sentence |
|---|---|
| `Trade offer` | `Declined a <Club> offer of <In> for <Out>.` / `Acquired <In> from the <Club> for <Out>.` |
| `Waivers` | `Claimed <who> off waivers.` / `Did not claim <who> off waivers.` |
| `Assignment` | `Assigned <who> to the <Partner>.` |
| `Signing` | `Signed <who>.` |

`Out` is what NYI sends, `In` is what NYI gets - an offer of `In` for `Out`. Semicolons
split a cell into pieces (`bits_of`), and a leading `X. Surname` that matches the roster
becomes a clickable name (`piece`). A new `Type` falls through to a generic line: add a
branch rather than letting it.

The Front Office ledger keeps the same rows as a table - columns, not prose. Both read
the one sheet, so nothing can drift.

## 5. Invariants that must survive every regeneration

- **Pure ASCII output.** `assert_ascii` runs over `chrome.css`, `extra.css`, `site.js`
  and the finished page. Entity-escape HTML (`&middot;`, `&ndash;`), `\u2013` in JS,
  `\25B2`-style in CSS. Some mobile webviews decode as Latin-1 and mojibake the rest.
- **No instruction text.** Section subtitles carry data only - never "tap a tile for...".
- **Empty sections render `empty()`**, so a 0-0-0 page looks deliberate rather than broken.
- **Every table is sortable and totals rows are locked.** Pass a totals row as `table(...,
  tfoot=[...])`; `site.js` refuses to sort `tfoot` and any `tr.tot` it finds in a `tbody`.
- **Unknowns sort to the bottom** in both directions - `site.js` treats `""`, `-` and `n/a`
  as unknown. Opponent assists render `n/a` because they are not tracked; only an NYI goal
  with no assists prints `unassisted`.
- **Nothing scrolls sideways - tables or grids.** A grid track written `1fr` is
  `minmax(auto, 1fr)` and grows past its share, so strips use `repeat(n, minmax(0, 1fr))`
  and `.stat .v` carries `flex-wrap: wrap` (its `<small>` is `nowrap` and would otherwise
  set the tile's floor). The strip is three across under 560px. Check
  `document.documentElement.scrollWidth` against the viewport on **every tab** at 360 and
  390px after any layout change; a single wide value on one tab is enough to break it.
- **A table must fit its column.** The chrome's default is `tbody td { white-space: nowrap }`,
  which pushes the last column off-screen. A table carrying prose needs `table-layout: fixed`,
  per-column widths and `white-space: normal; overflow-wrap: anywhere`. Verify at 390px.
  A `nowrap` chip inside a cell sets that column's floor - the 42px Team column in the
  ledger is why a non-NHL partner renders as an initials tile (`affil_tile`) and not its name.
  Only prose gets `table-layout: fixed`; a table of names and money sizes to its content.
- **Money never carries trailing zeros.** `mnum()` formats every figure; `$104M`, `$0.975M`.
- **Player names are clickable wherever they appear**, editorial copy included. Photos at
  `site/logos/players/<pkey>.png`; the crest stands in until one exists.
- **`version.txt` and `<meta name="build">` must match.** `deploy.sh` checks; `site.js`
  fetches `version.txt` with `no-store` and reloads through `?v=` once per build.

## 6. CSS layout

- `chrome.css` is the Royals port, kept diffable - change it only for a real chrome change.
- `extra.css` is the hockey-only layer and loads second, so it wins. New component styles
  go here.
- Both are indented two spaces at the top level, matching the port.
